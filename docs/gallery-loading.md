# 图库加载与大图库数据窗口

本次改造覆盖首页（全部、文件夹、标签、收藏、未分组）和普通／智能相册。搜索结果与序列保持原查询、排序和数组调用方式，共用新的图片调度与卡片资源选择。详情、选择和灯箱继续使用照片 ID。

## 图片链路

卡片按实际显示长边乘窗口 DPR 选择 256、512、1024、2048 物理像素档位，通过经过认证的 `/photo-thumbnail` 获取资源。入口只接受照片 ID 与固定档位；宿主检查删除状态和路径授权。来源文件身份包含大小、修改时间及变更时间，变体文件名还包含来源路径、生成版本和档位。旧 `thumbnailPath`、`thumbnailSmallPath` 和 HTTP 入口仍兼容。

宿主优先复用方向已经修正且分辨率足够的旧预览。原图小于档位时，以原图最大分辨率为上限。损坏、缺失或来源变化时按需生成并原子写入缓存。校验 LRU 使用规范路径及文件大小、mtime、ctime、birthtime；同一身份共享正在执行的校验。失败不会写成成功缓存。

共享调度器使用原生图片加载与解码，不保存长期 Blob URL。任务按 URL 合并，消费方退出后释放，最后一个消费方取消排队或尽力取消已开始的浏览器请求。前台生成、HTTP 恢复与维护共用生成队列。原生生成一旦开始可安全完成；过期消费方不接收结果。切换档位时保留已显示资源，升级失败仍保留小图。

图片请求窗口与 DOM 虚拟窗口分开；速度按 px/ms 计算。前方预取随速度变化，后方保留半屏，滚动停止约 150ms 后补齐。可见缺失图片直接使用照片 ID 请求，后台的延迟修复不再是显示前提。

## 数据与布局

首页游标包含协议版本、查询指纹、排序字段值、ID 和数据版本。排序沿用 SQLite 的比较与空值行为，ID 稳定兜底。前后游标共享筛选条件，旧 offset 接口保留。0054 增量迁移增加版本记录、变更触发器及名称／大小组合索引，不清空数据或重建缩略图。

普通相册在宿主建立轻量成员快照，名称沿用本地化比较，大小沿用原比较器语义。2026-10-24 体验优化将日期排序统一为首页的文件日期语义：升序空值在前、降序空值在后，同日期按 ID 稳定兜底；小相册与排序 worker 共用比较器。智能相册复用规则求值后的成员快照；规则、成员及相关搜索数据版本变化后重建。相册序列归属查询覆盖整个相册，完整照片按窗口批量补齐，单批不超过 1000 个 ID。

`GalleryDataSource` 将常驻 ID、尺寸、时间和必要状态放入 1000 条一块的数值存储，完整照片放入独立有界缓存。缓存页按最多 100 条打包，稀疏可见照片不会各占一个源页。可见窗口优先保留；主动全选只保留 ID／轻量引用，执行操作时才分批获取完整记录。

布局以 1000 条为检查点保存列高、分组和可见性边界。追加只计算尾部；结构变化从最早受影响块计算。超过 5000 条的完整重排使用单个渲染 Worker。结果按查询与布局版本丢弃过期响应，照片顺序、几何、总高和可见窗口一起提交。等待期间保留上一版照片及几何。

内容补齐复用已有的成员映射、筛选后布局输入和数字几何；收藏、加载状态不触发几何重建。灯箱底部条带也只渲染当前横向窗口，避免十万张时创建十万个按钮。

普通浏览的收藏更新保留游标与几何；收藏筛选的成员发生变化时使用成员版本切换数据源，即使尺寸版本未变化，也不复用旧成员顺序。

分页响应只为前 24 条预读缩略图身份，避免等待整页原文件状态后才显示图库。其余挂载卡片通过共享描述符接口按需补齐；按 ID 批量读取照片只读取数据库元数据，不为选择或导出提前检查整批原文件。

分页游标过期使用显式的 `GALLERY_CURSOR_EXPIRED` IPC 错误代码传到渲染进程，避免普通错误被 RPC 统一脱敏后无法识别。前端立即重置相应查询并使用新版本游标恢复，不重试已经失效的游标；其他错误保留原有重试设置。标签、序列等成员变更仍使用原有版本校验。

短页追加或容器宽度变化后会重新检查离底部的距离；防抖或 500ms 重排暂停拦截的检查在保护期结束后补查。离开底部、没有后页、加载中或卸载时不会继续请求。分页观察器不因加载回调的函数身份变化而重建，避免最终失败后反复触发；没有几何进展的失败不由布局补查自动重试。

启动时的孤儿记录核对使用最多 2 个异步文件检查，避免每批同步检查阻塞图片请求。只有明确的路径不存在才进入候选清理，权限和设备读取错误保留记录；清理前再次确认文件与数据库路径，停止服务时取消并等待后台核对完成。

深处返回通过照片 ID、相邻 ID 和视口偏移恢复；缓存淘汰后直接读取轻量前缀和目标窗口。已删除锚点优先落到原相邻照片。用户滚动可取消程序恢复。Shift 范围与相册全选依据完整成员顺序，缓存淘汰不清空选择。

灯箱关闭清理只在焦点仍属于灯箱或没有有效焦点时恢复打开位置；图库已经恢复到目标照片的焦点会保留，恢复焦点使用 `preventScroll`。

同一查询追加分页时，暂时保留的已显示卡片继续接受交互，避免 Chromium 因短暂的 `inert` 状态清除返回焦点；切换文件夹、筛选或照片／序列模式时，旧快照仍会阻止交互。远距离灯箱返回测试要求焦点与目标可见状态连续保持至少 250ms，避免把瞬间获得焦点当作成功。

## 默认预算

参数集中在 `src/utils/gallery-config.ts`，不增加性能设置页面。

| 项目 | 默认值 |
| --- | --- |
| 图片加载／非可见预取 | 6／2 |
| 生成并发 | 4 |
| 加载超时／重试 | 8 秒；仅可见暂时性超时重试一次 |
| 校验缓存 | 4096 条 |
| 每页预读缩略图身份 | 前 24 条；其余按挂载窗口读取 |
| 后台文件存在性检查并发 | 2 |
| 磁盘预算／文件保护上限 | 原有 20GiB／400000 |
| 自动磁盘核对最短间隔 | 5 分钟，单任务 |
| 启动首次后台核对 | 延后 30 秒，让首屏优先读取与解码 |
| 首页页大小／接口最大值 | 100／200 |
| 每上下文完整照片 | 20 页、2000 条、估算 16MiB，先达到者生效 |
| 上下文／宿主相册快照 | 最多 3 个，闲置 5 分钟回收 |
| 布局块／完整重排 Worker 阈值 | 1000／5000 |

数字尺寸索引约 4.8MB／十万条，几何约 4MB／十万条；这不是整个渲染进程的内存。React、ID 映射、代理、分组、Chromium 解码缓存及临时操作数据另外计入进程内存。16MiB 为完整照片缓存的序列化估算上限，不是浏览器堆上限。

照片代理共用读取处理器，避免为每张照片保留多组闭包。当前可见窗口有轻量保活，闲置回收针对没有挂载消费方的上下文。服务关闭会取消排队生成、等待已开始的生成与磁盘核对结束，再关闭数据库和切换数据目录；路径授权缓存同步失效。缓存清理只匹配宿主管理的哈希文件名，保留目录中无关的图片。

文件监听由单个共享宿主 Worker 注册，避免原生 `fs.watch` 在大目录初始化时阻塞主进程图片 HTTP 与 IPC。原有 Chokidar 忽略、深度和稳定写入选项保持一致，新增／删除事件仍回到索引服务处理；最后一个监听关闭后等待该线程退出，目录切换不保留旧事件。

Worker 动态加载的 `chokidar` 和 `readdirp` 必须随宿主打包，不能只依赖 Vite 的静态 import 分析。打包后可用原有真实目录移动回归验证，测试只修改隔离 EXE 副本的检查 fuse，同时核对原始文件与 `app.asar` 哈希：

```powershell
$env:AIM_PACKAGED_E2E_EXECUTABLE = (Resolve-Path "out/AI Image Manager-win32-x64/ai-image-manager.exe").Path
npm run test:e2e -- --no-build --workers=1 --retries=0 src/tests/e2e/watcher-folder-relation.spec.ts
Remove-Item Env:AIM_PACKAGED_E2E_EXECUTABLE
```

## 采集与复现

正常打包运行默认关闭采集。测试启动时设置 `AIM_GALLERY_PERF=1`，主进程通过 preload 的显式参数授权。采集实际 rAF 帧间隔、长任务、首屏 80%、停止滚动后 95%、占位比例、SQL／布局、图片排队／读取／解码及宿主缓存／生成计数。滚动回调耗时单独记录，不当作 FPS。

```powershell
npm run package
node scripts/gallery-baseline-build.mjs <基线提交>
node scripts/gallery-perf-auto.mjs --app=<基线目录> --count=10000 --runs=5 --scenario=baseline --trace=1
node scripts/gallery-perf-auto.mjs --count=10000 --runs=5 --scenario=optimized --trace=1
node scripts/gallery-perf-auto.mjs --count=10000 --runs=5 --seconds=5 --entry-metric=1 --scenario=gallery-entry --trace=1
node scripts/gallery-perf-auto.mjs --count=100000 --runs=5 --view=both --pattern=deep --anchor=90000 --scenario=pressure --trace=1
node scripts/gallery-perf-report.mjs reports/gallery/<场景目录>/summary-home.json
```

`--width`、`--height`、`--dpr` 控制窗口；`--cache` 支持 `browser-cold`、`warm`、`missing`、`corrupt`。`--album-kind=smart --view=album` 使用真实文件格式规则匹配完整图库，验证智能相册快照与分页。每张合成照片有独立 URL 和独立内容，包含横竖图、极端比例及缺失尺寸。冷缓存只表示应用／Chromium 缓存状态，不表示清空操作系统文件缓存。`--gate=<文件>` 可在造数完成后等待其他检查结束，再开始计时。

`warm` 在同一进程、端口和认证令牌下，先完整浏览并确认每张测试照片解码，再回到顶部预热完成后重新载入计时；报告的 `cachePrime.images` 必须等于数据量。仅跳过清理缓存不视为完成预热。宿主计数覆盖该进程生命周期，包含这一预热过程；页面的计时样本在重载后重新采集。

默认测量生产编译产物的目录启动方式，标记为 `production-bundle`。`--executable="out/AI Image Manager-win32-x64/ai-image-manager.exe"` 选择打包 EXE；正式包的 fuse 禁用了主进程调试，需同时传 `--instrument-executable=1`：采集器在隔离目录复制应用，仅对副本开启主进程检查，保留相同的 `app.asar`，标记为 `packaged-inspection`。报告记录原始／副本 EXE 哈希、前后 fuse 和实际 `app.asar` SHA-256，并确认原始 EXE 未修改。对比脚本禁止混用构建类型。原始 EXE 的启动退出另外验证。窗口／DPI 矩阵可通过 `node scripts/gallery-validation-matrix.mjs --from=final-1k` 从指定场景顺序执行；打包组覆盖万张首页与相册的深处浏览。

报告保存每次 JSON、截图、构建哈希、源码信息、硬件、Electron 版本、窗口、DPR 和缓存条件；未进入图库、数据量不符或样本无效均失败并保留诊断。性能样本最多保留每项最近 2048 个，count／total／max 记录整个采集期。完整时间线在 trace 文件中。

`firstViewport80Ms` 从瀑布流容器挂载开始，描述图片加载阶段。`--entry-metric=1` 另外记录 `entryFirstViewport80Ms`：首页从工具栏首次挂载开始，相册从路由导航开始，将随后的查询和布局准备计入。比较时可在 `gallery-perf-compare.mjs` 的输出前缀后传入 `entryFirstViewport80Ms`，两组必须使用相同起点与操作时长。该指标不是整个应用的启动耗时。

`--cpu-profile=1` 仅用于定位瓶颈，保存首屏前主进程与渲染进程 CPU 轨迹；对比脚本拒绝将 CPU 诊断样本用于验收。汇总工具对小样本 P95／P99 统一使用最近秩法，不丢掉五次中的最慢一次。

React 生产普通构建不提供 Profiler 回调。专项采集可使用 `AIM_GALLERY_PROFILE_BUILD=1` 构建，在运行采集开关同时开启时记录 React 渲染耗时、提交阶段 effects、被动 effects 及从渲染开始到提交的间隔。effects 耗时不包含整个 DOM 修改阶段；开始到提交的间隔包含渲染与等待，两者都不能称为纯 DOM 提交耗时。基线和优化对比必须使用同一种构建。

## 兼容范围与限制

- 搜索和序列结果本轮仍保留原数组协议；其完整对象缓存未改为分页窗口。
- 首页只对已扩展的业务范围全选，相册对当前模式完整范围全选。
- 选择、导出等主动操作可能临时持有超过窗口预算的数据；操作结束后不作为浏览缓存固定。
- 相册排序快照及深处定位的轻量前缀仍有一次与成员数量相关的准备成本；建立后取页不按深度扫描完整照片。
- 瀑布流优化最初保留旧相册日期语义；后续体验优化已统一为文件日期排序，未改为 EXIF 拍摄日期。
- 实际物理跨显示器移动、真实 RAW／权限故障及不同硬件的极限表现，以专项实测记录为准，不从合成数据推断已完成。
