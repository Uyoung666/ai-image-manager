# 网格密度加载优化验证

## 范围与状态

对比基线为 `9546f7d199c7ae4f5b780c7a704cca1c058e84bd`。覆盖首页、相册、搜索和序列共用的图片链路；保留现有排序、选择、位置恢复和 15% 中性色占位。没有数据库迁移，不自动提交或推送。

当前状态：**代码与本轮验证已完成，保留两项旧缓存收益目标未达的限制**。最终构建完成 13 组前后对比，各组每构建五次，以及窗口／DPI／缓存和轨迹专项；单元测试、类型检查、格式／lint、打包、十万张压力及完整 E2E 均已完成。本文只引用最终复验构建的收益，旧优化构建的结果不作为本轮交付结论。

## 用户可以看到的变化

- 小网格的所有可见卡片优先请求。尚未开始的离屏候选最多 12 个，不再随挂载卡片数量持续增加。
- 列表不再固定等待前 24 张照片的源文件状态；可见照片直接使用经过认证的照片 ID 入口。
- 已有准确档位优先读取。只有较大旧中图时，可以先复用足够清晰的现有资源，停稳后准备准确小档位供以后使用；当前图片不切换成模糊预览。
- 缩小网格保留已解码大图。放大或提高 DPI 时，仅对资源不足的卡片升级，失败保留原图。
- 快速滚动的一批取消先完成，再启动补充任务，避免启动马上又取消的旧任务。文件校验期间取消的请求不会继续创建生成任务。
- 首次校验小于等于 256KiB 的缩略图时，校验和响应共用读取结果。缓冲区只用于当前请求；校验缓存长期只保留元数据。

物理档位为 256、512、1024、2048。极端比例图片需要根据裁切比例选择更高档位；原始宽高缺失时保守选择 2048，避免根据卡片比例低估真实裁切需求，原文件小于档位时不放大。

准确变体和严格档位入口返回符合目标档位的资源。首次缺少档位时，`select=1` 显式资源选择入口可以直接复用足够清晰、方向正确的较大旧预览，停稳 500ms 后低优先准备准确小档位，避免强制缩图阻塞当前显示。因此不能把所有选择响应都描述为准确档位。选择响应的浏览器新鲜期为 1 秒，过期重新验证；匹配真实来源身份的严格档位 URL 才能使用 immutable。

图片像素解码失败时，卡片针对同一来源和档位仅发起一次 `repair=1` 恢复请求，宿主跳过可能损坏的准确变体及旧预览，从原始来源重新生成。恢复响应使用 `private, no-cache`，避免再次命中原损坏内容；再次失败进入错误状态，升级失败仍保留已成功显示的旧图。

## 测量方法

测试机：Windows 11、i9-13900HX、约 16GiB RAM；Electron 41.1.1 / Chromium 146。仓库隔离 E2E 启动方式关闭硬件加速，前后构建使用相同条件。结果用于同机相对比较，不代表所有显卡、磁盘或真实 RAW 图库的绝对速度。

主要场景使用一万张独立 WebP 源文件和独立资源 URL，来源长边约 1024，包含横图、竖图、极端比例与缺失尺寸。每张图包含独立颜色和几何内容；这些合成图案的压缩率与纹理复杂度不能代表任意真实照片。基线和优化复用同一个已关闭的隔离配置，排序为日期降序；每次重新启动应用并清理 Chromium HTTP 缓存。配置偏好、Code Cache 与操作系统文件缓存可以保留。

首屏从图库工具栏挂载开始，到 80% 可见照片显示完成，包含前置查询及布局准备。停止补齐使用固定操作数后的最后一次主动停止，到 95% 可见照片完成；保留 150ms 的停止确认条件。每个主要场景各运行 5 次，P95 使用最近秩法，五次运行的 P95 是最慢一次。

连续滚动中的自动化命令可能产生超过 150ms 的短暂停顿。旧 `scrollStop95Ms` 会采集这些停顿，前后采样次数可能不同；因此本轮最终验收新增 `scriptedScrollStop95Ms`，只比较固定操作序列的最终停止。原指标仍在原始报告中保留作诊断，比较器拒绝混用滚动协议。早期时间预算协议报告不用于最终收益结论。

精确变体已生成、仅有旧中图、完整浏览器预热分别报告。首次从旧中图缩放准确档位的成本不能记作准确变体热命中。图片 HTTP 请求数量、返回图片实际像素、卡片尺寸、列数、可见／挂载数量及缓存峰值随每次 JSON 保存。
